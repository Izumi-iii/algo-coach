# 中国站提交与判题接入研究

日期：2026-10-21。范围为个人本地 AlgoCoach，不涉及比赛自动化、批量刷提交或读取他人账号。本文是研究与设计建议，不代表提交后端已实现。

后续实现更新：已新增独立的实验性 CLI 后端及模拟接口测试，尚未完成真实账号验收；当前操作以 [平台提交指南](PLATFORM_JUDGE.md) 为准。下文保留接入前的研究结论。

## 结论

**技术上存在可复用的提交与结果查询流程，值得优先验证；暂缓把本地判题适配器从 2 题扩到 10 题。** 如果认证后的中国站小样本成功，平台提交可作为主要正确性验证来源，AlgoCoach 负责教学、版本绑定、结果解释与归档，无需重建平台的测试集、语言环境和逐题判定器。

这个结论来自公开客户端源码及匿名只读查询，不是本机真实提交成功的结论。未找到可据以承诺第三方集成稳定性的官方公开提交 API 文档，也没有验证账号认证、当前提交响应、限流或跨日可用性。未获得平台针对本项目的第三方接入授权说明，部署或提供他人使用前应另行核实适用条件。

## 候选协议

以下来自公开客户端实现，需在用户允许的登录环境内逐项确认，而不是直接宣称当前中国站协议已验收：

| 操作 | 候选请求 | 用途 |
| --- | --- | --- |
| 读取题目信息 | `POST https://leetcode.cn/graphql/` | 取得 `questionId`、`questionFrontendId`、`titleSlug` 与语言模板 |
| 运行样例/自定义输入 | `POST https://leetcode.cn/problems/{slug}/interpret_solution/` | 运行提供的输入，客户端使用 `data_input`；任务可能返回 `interpret_id` |
| 正式提交 | `POST https://leetcode.cn/problems/{slug}/submit/` | 由平台判题，客户端读取 `submission_id` |
| 查询任务结果 | `GET https://leetcode.cn/submissions/detail/{id}/check/` | 读取排队、执行或终态结果 |

候选提交载荷核心字段为 `lang`、`question_id` 和 `typed_code`；客户端还使用运行类型等附加字段，最终以认证观察为准。`question_id` 取内部 `questionId`，不能填展示题号。题目 1 两者恰好相同，不证明其他题也相同。

本轮匿名最小查询成功：HTTP 200、无 GraphQL errors，第 1 题返回内部 ID `1`、展示 ID `1`、slug `two-sum`；`userStatus.isSignedIn=false`。这是唯一一次对中国站的应用侧探针，没有请求 submit、interpret 或 check，没有读取浏览器 Cookie，也没有保存账号信息。

**运行样例与正式提交必须分别记录。** 任务终态成功可能只表示任务处理完成；需要继续解析判题结论，不能把 HTTP 200、取得任务 ID、`state=SUCCESS` 或自定义输入运行成功映射为正式 Accepted。结果中可能包含错误类型、失败输入、实际/预期输出、运行时间、内存及测试数量，但字段是否存在需兼容；缺失不能补成 0 或假装获得完整隐藏用例。

## 对现有代码的影响

以下来自本仓库检查和设计判断，不是外部客户端已经替我们实现的能力：

1. `remote.py` 当前详情查询没有 `questionId`，`Problem` 也没有提交元数据。需要新增独立的远程提交定位信息，绑定站点、内部 ID、展示 ID、slug 和题源快照；不要靠模型猜 ID，也不要为此改写已有题面快照、破坏审核哈希。
2. `Verification` 当前以本地测试为中心，报告字段包括执行镜像和测试集版本。平台结果应使用独立 `PlatformSubmissionReport`，不把远程结果塞成伪造的 Docker 报告。
3. `validate_reply()` 当前禁止声称平台通过。只有接通平台结果、核对代码版本和正式提交终态后，才允许模型描述对应代码的 Accepted；已有规则不能先放开。
4. `teaching_evidence.py` 目前只匹配本地失败报告。后续应显式读取平台证据类型；平台失败输入若不能可靠解析为结构化数据，只作为有来源的原始文本展示，不能由模型解析后冒充可信结构。
5. Web 的“提交并分析”只是保存代码和模型分析。应另设“提交至 LeetCode”，避免用户以为普通聊天、代码保存或查看参考解会发布账号提交。

建议的职责分配：

```text
题源获取与教学、代码保存
          ↓ 用户显式选择
平台提交预览（站点 / 题目 / 语言 / 精确代码版本）
          ↓ 确认执行一次
LeetCode CN → submission_id → 有限轮询 → 平台报告
          ↓
绑定当前或历史代码版本 → 教学解释 / 复盘 / 归档

现有本地 Docker → 离线调试与工程回归，作为可选能力保留
```

平台报告至少记录：来源站点、操作类型、内部题目 ID、展示题号、slug、语言、提交代码的精确字节 SHA-256、任务/提交 ID、创建与查询时间、查询状态、平台判题结论及可用的错误信息。排队超时、登录失效、访问拒绝、未知结果与代码判错分别处理。

已有提交查询到的代码若能够读取，应与保存的精确提交内容再比对；用户只粘贴链接或输入“AC”不能直接升级为程序核验的 Accepted。仅用户声明的结果应保留为另一种证据来源。代码有包装或转换时分别保存用户代码和实际提交代码的哈希，不将旧结果转移给新草稿。

## 登录、重复提交和使用条件

- 登录态只用于固定中国站请求，不进入模型上下文、学习检查点、归档或运行日志。浏览器 Cookie 不放入 AlgoCoach 前端 localStorage。首个原型可使用进程内/受控环境注入，持久化认证需单独设计；不要自动遍历浏览器凭据库。
- 用户在原站完成登录及可能的验证。401、403、验证码或风控出现时停止并报告，不能一律当作 Cookie 过期，更不尝试绕过。
- 正式提交会新增平台账号记录，必须明确触发。教学重试、参考答案纠正、页面刷新都不自动提交。首版不做后台自动提交或批量提交。
- 提交前落盘意图，获得 ID 后立即保存，轮询有间隔与截止时间。提交请求超时但未知是否已受理时记为 `unknown`；不能自动重发 POST，也不能用本地请求 ID 假设平台支持幂等。
- 原始响应体、请求 Cookie、CSRF 和完整供应商错误不得进入可发布日志。未知返回结构保持未知，不当作 WA、RE 或 AC。

已查阅[中国站服务协议](https://leetcode.cn/terms-c/) §3.1.6、§3.1.7、§3.3：对未经授权的访问、第三方工具及平台外使用存在限制。开源客户端的存在不是平台授权证明；技术可行性与第三方使用条件需要分开确认。本记录不据此断言全部个人使用均违法，也不把匿名查询成功当作提交权限。

## 最小验证顺序与验收

1. **协议与模拟测试**：实现独立提交报告和状态机，冻结匿名/排队/AC/WA/CE/超时等合成响应；验证数据归属、脱敏及不重复提交。此时不启用账号提交。
2. **用户登录下的小样本**：取得允许使用的认证方式后，先只读确认登录和内部 ID，再显式运行一次给定样例。不要把这一步当正式提交验收。
3. **正式提交验收**：选一道公开普通 Python3 单方法题，经用户明确操作提交保存版本，验证任务 ID、平台详情页、代码哈希和终态一致；错误结果作为独立明确操作验证，不为了填测试矩阵自动刷账号记录。
4. **中断恢复**：已有 ID 的任务只继续查询；提交是否受理未知时停止自动动作。失效凭据、限流与未知字段不改变代码正确性状态。
5. **再决定替代范围**：成功后优先接入 Web 与归档。暂停以“至少 10 个本地适配器”为产品主线；保留现有两题和独立教学证据检查，不先删除已有能力。

如果直接接口稳定性或接入条件无法满足，可先提供“复制保存版本 → 打开原题 → 用户在站内提交 → 导入结果”的辅助流程。用户手工声明和程序读取结果应区分。浏览器扩展可作为进一步方案，让用户在原站提交并显式回传结果，减少 Cookie 导出需求，但仍需维护扩展权限、跨来源通信和版本绑定，不是零开发成本。

本轮交付仅为研究文档和只读证据。没有新增依赖、没有实现提交命令、没有改变本地判题、没有提交代码到 LeetCode、没有修改原有教学检查功能。
