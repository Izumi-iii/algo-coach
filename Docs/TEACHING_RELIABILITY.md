# 教学可靠性修正

## 本轮修正

1. **当前任务明确传递。** 模型在历史消息之后收到由应用状态生成的任务说明。`/answer` 明确要求完整思路、复杂度及 Python 实现；此前的“不要答案”或“只分析代码”不再覆盖用户更新后的明确请求。普通讨论不会因为历史中存在答案请求就自动视为新答案请求。
2. **答案交付检查。** 答案请求须返回 `hint_level_used=4`、`full_solution=true`，且包含可解析的 Python 代码块和题目方法的非空实现。只提问、只有标签、错误方法名、语法错误或 pass/省略号桩会触发有限重试。AST 检查不执行代码，也不能证明算法正确。
3. **有针对性的重试。** 程序提供固定白名单中的拒绝原因：提示越级、代码块、实现声明、无依据平台/测试结论、答案未交付。不向模型转发原始异常或供应商内容；未知错误仍使用安全通用类别。调用次数上限不变。
4. **保留失败请求。** 失败答案请求的 `/retry` 保留 `answer` 动作；代码请求保留 `code`。提示请求重试不会再次升级提示级别。答案只有实际交付后才记录为已展示，随后不得标记无提示独立完成。
5. **澄清已有方案评价的边界。** H0 可核对用户明确给出的方案与题意、复杂度，不添加用户尚未提出的算法或操作。低提示等级仍禁止代码块及完整实现；代码诊断优先使用行号和文字，避免重抄提交代码导致误拦截。该边界依赖语义复核，不能仅凭模型自报等级认定遵守。
6. **代码事实辅助诊断。** 新增 `code_facts.py`，只用 AST 提取当前代码的局部循环入口绑定及首个属性写入，并绑定原始代码哈希。事实同时出现在状态上下文和当轮任务中，用来核对“指针从未修改”等结论。历史助手回复不能作为事实来源。
7. **独立验证模型参考代码。** 真实模型的显式答案请求通过结构检查后，交给现有验证服务。Docker 已启用且适配器支持时，代码仅在容器中执行；判错、运行错误或执行器异常都会触发有限纠正，重试仍失败就受控结束，不展示失败实现为完整答案。模型不决定判题通过。验证器禁用或题型未支持时，仍可交付结构完整的答案，但明确附加未验证状态。

参考代码的每次验证记录保存在独立 `answer_checks`，不会替换 `current_code`、用户尝试或用户验证报告。实际交付的答案后附独立验证结果，不把该结果伪装成模型在生成时已知的事实。`/code` 依旧不自动执行用户代码，用户测试仍须显式 `/test`。演示模式不执行参考代码验证。

评估工具用 `--docker` 控制参考代码的动态验证，未开启时明确使用禁用执行器，即使用户日常 CLI 的 `.env` 已启用 Docker，也不会越过本次评估标志。

## 机械代码事实的范围

提取器只处理 while 紧邻前一条简单赋值、循环体直线前缀中的简单赋值与首个属性写入；遇到不支持的分支、调用或绑定更新会停止推导。它不执行用户代码、不解释任意 Python、不访问候选程序的文件或网络，也不证明循环进入次数、循环不变式或算法正确性。

事实里的表达式表示入口别名。例如入口 `p, c = tail, front.next`，若首轮执行 `c.next = p`，可得入口 `(front.next).next` 写为入口 `tail`。该结论依赖普通属性读写、无自定义副作用；不能推广为完整程序的正确性证明。AST 大于 4,000 节点时不展开循环事实，最多记录 12 个循环。

本功能从实际提交代码提取事实，不按题号或参考解哈希返回标准答案，不把评估评分预期交给模型。模型仍可能误解事实、错误估计循环次数或给出不充分推理，须保留语义复核和独立验证。

## 验收方式

- 工程测试覆盖答案交付、持久权限、重试动作、具体反馈脱敏，以及 AST 别名提取和不执行代码。
- 原 5 个失败场景定向真实模型复跑；读取实际回复，不能只看自动契约。
- 修正后的完整 30 场景再次运行，保持原评估集及评分契约不变。
- 从模型实际返回的两份完整答案中提取代码，使用 Docker 独立验证。验证结果只属于这些代码哈希和本地有限测试，不回填到原教学对话冒充当时已有的执行证据。
