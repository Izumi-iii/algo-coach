## 复核工具

新增独立模块 `evaluation.semantic_review`，离线运行，不调用模型、不修改正式人工报告。支持 `pass / fail / uncertain / na`，拒绝错运行、错步骤、重复记录和输出已改变的评分；所有记录固定标记 `review_kind=ai_assisted`，不能直接作为原 `HumanReview` 导入。原 `compare` 也复用步骤/调用哈希校验，拒绝已改变的模型输出。

```powershell
$run = '.algo-coach/evaluations/20261017T092321Z-eb2f0995'
.\.venv\Scripts\python.exe -m evaluation.semantic_review template $run --output "$run/assisted.template.jsonl"
.\.venv\Scripts\python.exe -m evaluation.semantic_review report $run --reviews Docs/evidence/teaching-assisted-review-2026-10-17.jsonl --output "$run/assisted.summary.json"
```

输出使用独占创建，已有文件不会被覆盖。正式人工复核继续使用 [评估指南](TEACHING_EVALUATION.md) 的人工模板及 `evaluation.runner report --reviews`，应独立核对 AI 标出的证据，而非直接改标签冒充人工评审。

## 本轮修正与回归

1. 模型在历史消息之后收到当前代码的编号快照、当前哈希及验证状态，最后的应用任务明确以该快照为准；保留原历史用于学习恢复，不再只依赖更早的状态 JSON。
2. AST 事实新增覆盖说明：`loops=[]` 只表示未匹配受支持的局部 while 模式，不能推出没有 for/while 或代码正确。
3. H1 的普通求助任务明确禁止先公布核心等式、遍历方法或修复步骤再包装成问题；这一提示约束不构成语义防泄露证明。
4. 首测发现“不能声称测试通过”被误认为肯定结论。已增加同一分句内的有限否定识别，不能把前句的否定延伸到“但/不过”后的肯定结论；并收窄匹配，避免一个匹配跨逗号吞掉后续断言。

定向工程回归 **132 passed**，Ruff 静态及格式检查通过。本轮没有重跑此前的完整工程、Docker 或中国站网络集成。3 个原场景定向真实运行自动契约 3/3，6 次调用、15,530 tokens；内容阅读仍发现虚构缺少 return、额外无必要追问等问题，未宣称提示修正解决了全部语义错误。

## 参考验证表述修正

针对补跑发现的两项披露错误，新增以下行为：

1. 生成参考答案时要求模型只写实现及静态讲解，不预先声明新参考代码的测试状态。交付时由应用标明静态讲解属于生成时刻，随后展示实际独立报告及展示代码的 SHA256；即使模型残留生成时的未测措辞，也明确区分前后时刻，不用正则删除可能有用的代码或分析。
2. 应用从最近一条含实现代码块的助手消息中，按与验证器相同的方式提取代码，使用原始字节计算哈希，只匹配 `answer_checks` 中哈希相同的报告。将对应关系放在历史消息后的新 `reference_snapshot` 中；参考代码报告不会取代用户 `verification`。用户消息中的代码块不参与参考绑定，较新但未展示的失败尝试也不会覆盖已展示代码的匹配报告。

新工程回归覆盖残留状态措辞的时序标记、展示/报告精确匹配、尾部换行改变时不借用旧报告、忽略用户伪造消息和未展示尝试，以及用户尚未提交代码时的新快照。定向 **93 passed**。随后启用 Docker 的完整工程回归 **305 passed、1 skipped**（包含 7 项真实 Docker 集成；跳过中国站网络集成），Ruff 静态、格式及差异检查通过。
