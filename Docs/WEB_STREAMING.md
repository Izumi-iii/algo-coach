# Web 对话流式输出与任务交互

更新日期：2026-10-22。

## 页面行为

- 移除顶部全宽等待横幅。聊天等待、继续回答和整理状态放在助手消息气泡内，以轻量圆点显示；错误信息仍明确显示。
- 生成期间可以继续编辑下一条消息和代码、展开题面、查看学习记录。切换会话不会让旧任务完成时把页面强行切回去；本页中的会话草稿分别保留，刷新当前会话也不覆盖正在编辑的内容。
- 再次发送、提示升级、保存分析、新建练习、执行测试、绑定报告和平台提交仍需等当前任务完成。这些操作会修改学习状态，仍使用现有串行写入机制；没有自动排队发送下一条草稿。
- 任务进行中可查看已缓存的只读会话快照，不与写入操作并发访问学习数据库。启动时缓存最近 32 个本模式会话，运行期最多 64 个；冷门、未缓存会话可能仍需等任务完成后读取。
- 页面刷新会恢复同一个任务；SSE 连接中断时退回读取原任务状态，不重新 POST。服务重启导致旧任务 ID 不存在时，仍要求恢复会话确认结果，不自动重发模型请求。

输入和代码草稿保留在当前页面内存中，不等同于持久化保存；刷新整个页面仍可能丢失未提交草稿。

## 流式机制与边界

真实模型使用原生工具调用流，而非把完整回复加延时模拟打字。`StreamTeachingReply` 要求先给出提示等级、阶段、完整答案标记和证据字段，再给正文；正文的完整段落到达时，应用对**累计正文前缀**运行同一套提示权限、来源和样例证据检查，通过后才发布预览。

浏览器订阅 `GET /api/jobs/<id>/events` 接收状态及已检查段落。服务只存储当前预览快照和递增序号，不保存无限 token 事件列表；断线重连直接读取最新快照，客户端不会重复追加相同段落。

以下情况会先缓冲，不保证逐字到达：

- 模型没有先输出完整证据字段，或没有产生完整空行段落边界；
- 段落前缀尚不能通过检查；
- H3/H4 或完整答案：等整份回复及既有参考解检查完成后再显示。

因此，这是**模型生成过程中的、经过前缀检查的分段流**，不是未经检查的逐 token 展示。普通 CLI 和原有批量评估仍走原整份结构化调用路径；Web 使用新增流式路径。

预览仍属于生成中的内容，只有最终回复才写入会话。若完整回复不通过而重试，页面清除当前预览并显示调整状态；预览中已读到的文字无法撤销。有限规则无法证明自由文本的全部语义正确，既有教学准确性限制仍然存在。

## 复跑浏览器验证

使用隔离目录启动离线延迟流 fixture，不会调用模型或提交原站：

```powershell
.\.venv\Scripts\python.exe scripts/web_stream_fixture.py --port 8768 --data-dir .algo-coach/web-stream-preview/sessions
```

另启动使用独立用户目录、开放本机 DevTools 9224 端口的 Chromium，然后运行：

```powershell
node --max-old-space-size=128 scripts/web_stream_browser.cjs http://127.0.0.1:8768 http://127.0.0.1:9224
```

浏览器验证拒绝真实模型模式。查看真实效果时使用正常模型 Web 入口，并在更新服务后强制刷新页面。
