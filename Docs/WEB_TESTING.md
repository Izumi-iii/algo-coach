# 本地 Web 测试界面

## 启动

使用项目已有虚拟环境和 `.env`，不需要安装前端工具链或新增运行依赖。在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m algo_coach.web --data-dir .algo-coach/web --port 8765
```

在浏览器打开 <http://127.0.0.1:8765>。这是实际模型模式：题目、对话和提交的代码会发送给现有 `.env` 配置的模型服务；打开页面、恢复会话和查看报告本身不调用模型。终端按 Ctrl+C 停止，已完成的会话保存在指定目录。

无模型体验：

```powershell
.\.venv\Scripts\python.exe -m algo_coach.web --demo --data-dir .algo-coach/web-demo --port 8766
```

演示教学使用脚本回复，不理解用户思路；如果执行器已启用，单独点击测试仍会调用真实 Docker 验证用户提交代码。模型与演示会话按模式分开显示，不能互相当作真实教学会话。

省略 `--data-dir` 时沿用 `ALGOCOACH_DATA_DIR`，未配置时为 `.algo-coach`，与 CLI 一致。若目录正被 CLI 或另一 Web 进程使用，启动会明确报错，不绕过锁。要恢复原有 CLI 历史，先正常退出使用该目录的 CLI，再启动：

```powershell
.\.venv\Scripts\python.exe -m algo_coach.web --data-dir .algo-coach --port 8765
```

目前这台机器的默认目录有既有进程持有锁，因此已启动的 Web 使用独立 `.algo-coach/web`。它不会自动复制、迁移或合并原有历史。

## 页面流程

1. 左侧选择本地题库或中国站，输入 `1`、`leetcode25` 或中国站链接；中国站每日题选项会在点击开始后显式获取当前每日题。
2. 题目区常驻题号与标题，题面默认折叠；点击“展开题面”查看题意、约束、样例、方法签名、来源与缓存信息。“收起题面”会释放桌面聊天空间，浏览器记住展开偏好。远程失败不会悄悄替换成其他题目。
3. 对话区支持正常交流、提示、显式完整解答和失败后重试。Enter 发送、Shift+Enter 换行，中文输入法候选确认不会误发送。
4. 编辑器支持多行 Python、Tab 缩进和行号。点击“提交并分析”保存一个代码版本并调用教学逻辑，只做静态检查，不自动执行。
5. 点击“运行本地测试”才验证已提交版本，不调用教学模型。编辑器有未提交修改时该按钮禁用，并标明旧报告仅属于保存版本；后端还会核对代码哈希，拒绝其他窗口已改版后的陈旧测试请求。
6. 报告区显示实际执行情况、通过数、版本与首个失败用例；参考解独立报告放在单独区域，不覆盖用户报告。
7. 左侧可恢复历史会话；页面刷新可恢复最近会话和仍在本服务运行中的任务。服务重启后任务状态不再保留，但已完成学习数据仍可恢复。任务状态未知时不自动重发模型请求。

未提交草稿只存在当前页面，刷新或关闭可能丢失；切换题目/会话时会确认未提交代码和消息。聊天返回不会用参考答案替换用户代码，也不会覆盖当前未提交草稿。

网页将系统开场消息中的重复题面缩为开场提问，完整原始消息仍保存在会话中；后续对话和仅展示最近 100 条的截断历史不会按这个规则缩写。

## 实现与边界

- `src/algo_coach/web.py` 使用标准库 HTTP 服务适配 `Coach`，页面资源位于 `web_assets/`，不引入第二套教学或判题逻辑。
- 只监听 `127.0.0.1`，不提供公网或局域网监听选项；这是个人本机测试入口，没有多用户认证或生产部署承诺。
- 所有 Coach 操作串行；长操作通过后台任务和状态轮询显示，不伪装成模型流式输出。HTTP 测试覆盖重复请求 ID 去重、并发操作拒绝和错误后的恢复。去重仅保留最近 64 项，不能保证跨服务重启的请求去重。
- 写接口校验本机 Host、同源 Origin 和页面令牌；只暴露建会话、聊天、代码提交、测试及环境检查，不暴露任意文件读取、归档或 Git 执行接口。
- 题面和模型回复通过文本节点渲染，不执行其 HTML；有安全响应头，不依赖第三方 CDN。Markdown 只对代码围栏做简易展示，未实现完整 Markdown、语法高亮或高级 IDE 功能。
- 页面仅展示当前模式会话、最近 100 条消息和最近 10 个参考报告，完整历史仍保存在本地。
- 判题仍受原有适配器限制：目前第 1、25 题及已审核题面版本。其他题可获取并讨论，但不能把 `unsupported` 当成判错。教学内容的历史叙述和反例问题仍存在，见 [响应可靠性记录](RESPONSE_FOCUS_2026-10-18.md)。

## 验证方式与本轮结果

HTTP 回归使用真实 Coach、临时 SQLite、显式演示教学和模拟判题报告，不调用付费 API：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_web.py -q
node --check src/algo_coach/web_assets/app.js
```

当前 7 项 HTTP 测试通过，覆盖完整会话流程、刷新/重启持久化、来源路由、过期代码哈希、同源边界、禁止任意文件访问、任务去重/串行和异常信息控制。

使用本机已有 Edge 的隔离无头浏览器，以及 Node 内置 fetch/WebSocket 做了真实浏览器验收。`scripts/web_browser_smoke.cjs` 只允许演示模式，避免误发付费请求；它验证选题、提示、代码提交、报告、刷新恢复、草稿保留、旧草稿禁测、HTML 文本安全、手机宽度及浏览器异常。加 `--docker` 时要求错误代码取得真实判错报告。

```powershell
# 前置：独立 demo 服务在 8766，隔离 Chromium 调试实例在 127.0.0.1:9223
node scripts/web_browser_smoke.cjs http://127.0.0.1:8766 http://127.0.0.1:9223 --docker
```

本轮桌面 1440×1050、手机 390×844 检查通过，无横向溢出或未捕获浏览器异常；截图在本机 `.algo-coach/web-preview/`。真实模型模式另完成两次教学操作（对话、代码分析），随后显式 Docker 测试错误代码为 `wrong_answer`、0/47，并从接口恢复保存的代码；没有测试远程中国站网页路由的实际网络获取，来源路由只用了模拟来源方法验证。

源码方式启动已验证。曾尝试无安装的离线 wheel 构建，但当前虚拟环境没有 setuptools，未完成该构建；没有为此安装工具。静态资源已声明为包数据，不能把声明当成已验证的安装包交付。

最终完整工程回归 **351 passed、1 skipped**，含 7 项真实 Docker 集成。Ruff、格式、两份 JavaScript 的语法及差异检查通过；来源网络集成未启用。验证范围、资源哈希与截图索引见 [本轮证据](evidence/web-testing-2026-10-18.json)。
