# 重复值覆盖误诊修正与复验

## 修正依据与边界

两数之和要求两个不同位置，未要求最早下标。若两个已处理位置 j、k 的值相同，且二者均不同于当前 i，则用 j 或 k 与 i 配对，和值相同、位置也仍不同。故“字典覆盖同值旧下标”本身不能作为缺陷。

先把当前 i 写入字典再查询，则可能在两倍当前值等于 target 时命中 i 自身。必须把这个自配对问题与等值旧下标的替换分开。反例还须满足长度及唯一解保证，例如 `[2,2,5], target=7` 有两对和值合法的下标，不是唯一解题面的合格反例。

应用新增这段约束推理，只绑定内置或已审核快照的 `two_sum` 适配器。修改成“要求最早下标”的题面、其他题目、不完整题面不会使用它。只在有用户代码或显式要答案时提供，普通题意澄清不添加新算法引导。这是供模型核对的数学依据，不是对任意提交代码的静态证明或运行结论，也没有增加一个声称能判定自然语言正误的正则过滤器。

工程测试检查题面绑定、变体拒绝、H0 边界以及等值已处理位置替换的有限枚举性质，未在宿主执行提交代码。最终完整工程回归 **310 passed、1 skipped**（含 7 项真实 Docker 集成；中国站网络集成未启用），Ruff 静态与格式检查、差异检查通过。

## 内容复核与后续工作

本轮三次运行合计 **17 次调用、61,320 tokens**，成本 unknown。16 个模型步骤全部进行明确标记的离线 AI 辅助复核，5 步至少一项 fail；正式人工评分仍为 0。辅助评分绑定运行、步骤与输出哈希。

修正后回归没有再把覆盖旧下标当作第二个缺陷，但模型仍会用 `[1,1], target=2` 说明现有先写后查代码发生第二轮覆盖，忽略首轮已经返回。这是不可达动作的解释错误。此外还出现把“两倍当前值等于 target”写成“当前值的一半等于 target”的措辞错误。数学依据提高了诊断约束，未保证模型正确使用它。

下一步优先处理沿用旧版本诊断、忽略 return 后不可达代码以及在已能直接回答时机械追问。应先建立当前版本的局部控制流证据，明确覆盖范围，再用新的未用于调整的场景验证；不能仅用更多提示词宣称解决。
