# 当前代码顺序与提前返回的教学可靠性修正

## 问题与修正

此前真实模型回复存在两类已复现误读：换成先查后写版本后，继续沿用旧版先写后查诊断；分析 `[1,1], target=2` 的先写后查版本时，忽略首轮已返回 `[0,0]`，把第二轮覆盖旧下标描述成实际发生。

新增 `code_facts.mapping_scans`，由 AST 提取当前代码的空字典初始化、循环、查询、写入和 return 行号，以及写入/查询的实际顺序。事实绑定当前代码 SHA256，在历史消息后的快照与最终应用任务中提供，避免只依赖模型重新阅读旧对话。

对精确匹配的模板，规则提供有条件的局部事实：

- 先写后查：若 `target == 2*nums[0]`，首轮空字典写入后查询命中并返回 `[0,0]`，没有覆盖旧下标，不进入第二轮。
- 先查后写：首轮查询空字典不命中，之后写入；命中时 return 结束函数，本轮后面的写入和下一轮均不会发生。

应用任务要求模型区分实际路径与明确标注的反事实路径；按当前行号检查历史诊断；用户只核对局部事实时直接回答，不把它当作需要升级提示或提供完整修复实现的理由。

## 静态证据的边界

这不是通用 Python 控制流分析器，不执行提交，不调用 `eval/exec`，不证明整段程序正确或已通过测试。只识别普通整数列表、整数目标和内置 `enumerate` 条件下的严格模板：空字典初始化，双变量枚举，直接补数查询或局部补数变量，单个命中 return，单个下标写入，可选循环后 return/raise。

额外分支、函数调用、变量重绑定、`try/finally`、`yield`、非空初始字典、不同返回形式和带 start 参数的 enumerate 不获得这类控制流结论。超出 4,000 个 AST 节点时跳过，最多提取 12 个匹配。`mapping_scans=[]` 仅表示未匹配，不表示没有循环、没有 return 或代码正确。

原有 `loops` 链表局部赋值事实保持独立。事实仍有明确前提，不能被模型当成任意输入、任意对象或其他未支持代码的证明。

## 内容复核及剩余限制

逐条读取并明确标记为 AI 辅助复核的 16 个模型步骤中，本轮没有再次观察到目标顺序误读或把 return 后不可达动作描述成实际发生。这个结论限于本轮样本，不能保证模型以后始终遵守局部事实，更不能视为所有控制流或新题型的正确率。

仍发现其他内容问题：新版本回复把题意写成“两个不同位置且和不相同”；某些回复把版本已经更换说成“上一轮误判”，混淆旧版正确诊断与新版适用范围；用户只求直接结论时仍追加追问；还会混淆已证明的局部性质与“只是没找到反例”。辅助复核共 4 步至少一项 fail、12 步含 uncertain，可重叠，正式人工评分仍为 0。因此没有把自动契约通过率当成整体教学质量通过率。

下一步应处理版本叙述与不必要追问，并继续扩大不同控制流写法的覆盖；新规则不支持的代码必须明确保留“不足以判定”，不要为了覆盖更多语法而输出未经验证的推论。
