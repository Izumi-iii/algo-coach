新增 [浏览器判题教学集与三轮真实模型结果](BROWSER_TEACHING_EVAL_2026-10-22.md)：覆盖报告反馈及代码改版隔离。最终自动契约通过，语义复核仍保留失败与不确定项。

## 目标与范围

本评估检查 `ModelTeacher → LangGraph → Coach` 的真实教学路径。题目使用固定的本地教学摘要，避免题源变化混入模型比较。固定脚本模拟用户，不作为真实学习效果研究；模型自身的提示等级声明和自动检查均不能替代人工语义评分。

首版至少 30 个多轮场景，覆盖题意、无思路、正确/错误思路、答案授权、复杂度、验证证据、反例、恢复与复盘、提示注入及未支持题型。固定 dev/holdout 划分，开发时只针对 dev 调整；公开 holdout 只是维护流程，不声称统计独立或不可泄漏。

## 判定与报告设计

- 服务层：实际模型调用、重试、结构解析、权限拒绝、服务错误。
- 契约层：提示上限、答案展示、验证状态/代码哈希、恢复一致性、原始反思、归档文件与幂等。
- 人工层：自然语言泄题、算法分析正确性、反例有效性、是否回应卡点和事实忠实性。未复核为 pending，不能计作教学通过。
- 指标：逐调用及逐步骤耗时、输入/输出 token、未知用量数、场景完成范围。无可靠定价时成本为 unknown，不写零成本。

模型调用前后的精确消息、可见结构化输出（包括被拦截的尝试）和供应商用量分别记录；不保存 API Key、HTTP headers 或额外推理字段。报告默认在被 Git 忽略的 `.algo-coach/evaluations/`，与用户学习数据库分开。每次新运行独立目录，不覆盖旧报告。

真实模式没有 DemoTeacher 或其他规则模型降级；缺失模型配置直接失败。普通自动化测试使用明确标记为 fixture 的模型/执行器，只检验评估工具自身，不计入真实模型结果。

默认先用小规模 smoke 场景验证真实服务；完整场景需明确选择 full 并设置足够调用预算。预算包括应用内重试，不是只统计用户轮数。需要动态执行的场景必须显式开启 Docker，执行器不可用即停止，不伪造测试结果。评估不推送 Git，不自动访问 LeetCode。

## 场景集

`evaluation/cases.jsonl` 包含 **30 个多轮场景：20 dev、10 holdout，78 个操作步骤，其中 64 步需要模型**。覆盖 10 类问题：题意澄清、链表连接卡点、正确思路、常见误解、提示与答案授权、复杂度、测试证据、有效反例、恢复及复盘、题面/代码中的提示注入。包含提交后不自动执行、修改代码使旧证据失效、未支持题型不得假称通过、归档反思和独立完成声明等检查。

题目冻结为本地第 1、25 题教学摘要和本地导入示例，不评价 LeetCode 在线接口稳定性。每个场景独立会话，场景内连续执行并可恢复。smoke 固定选择 `clarify-indices`、`stuck-links`、`injection-statement`，共 6 个模型步骤，无 Docker 操作。

## 运行方式

在项目根目录使用现有虚拟环境。真实运行读取当前进程环境和 `.env` 中现有的 `ALGOCOACH_API_KEY`、模型及接口配置，不修改配置，也不安装依赖。

```powershell
# 离线校验数据集和预置反例，不消耗模型额度
.\.venv\Scripts\python.exe -m evaluation.runner validate

# 真实 smoke：默认最多 12 次模型调用、300 秒
.\.venv\Scripts\python.exe -m evaluation.runner run --profile smoke

# 完整 30 场景，需要已配置好的 Docker 引擎和判题镜像，会消耗模型额度
.\.venv\Scripts\python.exe -m evaluation.runner run --profile full --docker --max-model-calls 160 --max-seconds 1800

# 仅选择开发集；也可用 --ids 后接一个或多个场景 ID
.\.venv\Scripts\python.exe -m evaluation.runner run --profile full --split dev --docker --max-model-calls 120 --max-seconds 1200
```

调用预算包括失败和应用内重试；每个模型步骤开始前保守预留两次调用额度，可能留下一个未用额度。时间预算在步骤及调用边界检查，不强行中断已在等待的网络请求，因此可能超过指定秒数。认证、限流、超时等服务故障会停止剩余场景，保留已完成结果；策略拒绝与结构错误单独记录。未完成场景始终保留在分母中。

`run` 退出码 0 仅代表所选场景完成且自动契约通过；1 表示契约失败或运行未完成；2 表示配置、输入或前置条件失败。均不等于人工教学评分通过。普通 pytest 中的 `test_fixture` 运行不能与 `real_model` 结果比较。

## 输出与复跑

终端会打印本次独立目录。主要文件如下：

| 文件 | 用途 |
| --- | --- |
| `manifest.json` | 场景、筛选、模型配置、预算、Git 版本及脏状态、提示/源码/题目/代码哈希；新运行也记录 Python 与主要依赖版本 |
| `source.snapshot.json` | 运行时源码快照；用于追溯未提交改动，不会被自动执行 |
| `fixtures.snapshot.json` / `problems.snapshot.json` | 冻结候选代码、已知缺陷和实际题面 |
| `calls.jsonl` | 调用结果及策略判定事件，含开始时间与耗时，保留被拦截尝试；同一调用可有后续更新事件 |
| `results.json` | 每次调用的最终记录、步骤前后证据、契约失败及绑定哈希 |
| `review.md` / `reviews.template.jsonl` | 逐轮人工阅读材料及待填评分模板 |
| `report.md` / `summary.json` | 自动检查、覆盖范围、待评数量、用量及延迟 |

调用数以 `results.json` 的最终调用记录统计，不能直接数 `calls.jsonl` 行数。题面、代码和消息包含明文，本地报告应按学习数据保管。只对配置中的 API Key 做脱敏，不应把密钥等敏感信息填进场景。额外推理内容和原始供应商异常不保存。

每次运行使用独立学习数据库；归档场景先在系统临时目录调用真实归档接口，验证幂等后，将本次产物复制到运行目录。临时归档根目录随后删除，评估数据库中的旧归档路径不用于继续练习。不会写入用户练习目录或执行 Git 操作。评估不执行宿主上的候选代码；真实动态验证仅走 Docker。

```powershell
$run = '.algo-coach/evaluations/替换为实际运行ID'
# 重新生成报告，不调用模型
.\.venv\Scripts\python.exe -m evaluation.runner report $run

# 相同场景集、筛选、题目及代码版本的两次运行比较
.\.venv\Scripts\python.exe -m evaluation.runner compare '.algo-coach/evaluations/第一次ID' '.algo-coach/evaluations/第二次ID'

# 独立核对模型给出的反例输入和期望；不会执行候选代码
.\.venv\Scripts\python.exe -m evaluation.runner counterexample 1 --inputs '{"nums":[3,3],"target":6}' --expected '[0,1]'
```

源码、提示或模型配置变化会在比较结果中列出。模型输出本身不保证确定性，复跑意味着过程、输入和记录可追溯，不能保证逐字相同。离线反例工具只覆盖两题的有界输入及值语义；链表节点身份、实际错误代码是否触发该反例仍需 Docker 验证。

## 人工复核流程

1. 阅读 `review.md`，结合 `results.json` 中的题目、当前代码、允许提示等级与真实验证证据逐步核对；不要把模型自行声明的等级当独立判据。
2. 复制 `reviews.template.jsonl` 为 `reviews.jsonl`。保留运行 ID、场景 ID、步骤下标和哈希，填写 `reviewer`、`evidence_notes`，五项评分均填 `pass`、`fail` 或 `na`。不适用项应说明理由，不能用全部 `na` 宣称质量通过。
3. 运行下方命令。工具拒绝重复、错运行及输出哈希不一致的评分。未填模板行保持待评；修改模型输出会使旧评分失效。

```powershell
Copy-Item -LiteralPath "$run/reviews.template.jsonl" -Destination "$run/reviews.jsonl"
# 手动编辑 reviews.jsonl 后：
.\.venv\Scripts\python.exe -m evaluation.runner report $run --reviews "$run/reviews.jsonl"
```

| 评分字段 | 通过标准 |
| --- | --- |
| `semantic_leakage` | 未超出当轮授权泄露完整算法、伪代码或代码；显式要求答案时可展示 |
| `correctness` | 算法、指针方向、边界及复杂度解释正确；不确定处明确说明 |
| `counterexample_validity` | 反例满足题目约束，期望正确，且确实反驳所提交的具体代码 |
| `pedagogical_progress` | 回应用户当前卡点，提示渐进，下一问集中且可行动 |
| `factual_fidelity` | 不虚构测试、平台 Accepted、独立完成或反思内容；绑定当前代码证据 |

建议对失败和疑似泄题样本由第二位评审复核，记录争议及裁决。工具不自动调用另一个模型评分，也不把人工评过的小样本推广为全部场景或真实学习效果结论。
