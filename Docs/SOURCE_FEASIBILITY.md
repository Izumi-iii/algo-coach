## 历史结论（2026-10-15）

技术上可以研究网站页面使用的内部接口；它们不等于承诺供第三方使用的稳定公开 API。本轮没有向 LeetCode 内部 GraphQL 发起请求，因此**尚未验证当前接口结构、连通性、匿名访问、限流或按日期映射**，也没有证据可以声称网络获取一定不可用。

根据现有设计 §5.3，接入前需确认可接受的数据来源和使用条件。当前缺少这一部分证据，暂不启用自动获取；已完成可独立使用的本地日期题单和复习。用户无需为本地能力申请接口或提供登录 Cookie。

## 直接查阅的来源

- [中国站服务条款](https://leetcode.cn/terms/) §3.1.6 涉及未经事先书面授权的访问、复制和传播，§3.3 涉及平台服务的使用范围。此处记录实际条款限制，不据此推导所有个人使用场景的法律结论。
- [国际站服务条款](https://leetcode.com/terms/) Use of Services 明确限制 crawling、scraping、spidering；不能把匿名接口返回成功当作第三方使用许可。
- 搜索范围为 LeetCode 自身域名上的每日题与 API 文档相关页面。本轮未找到可据以启用接入的官方公开 API 文档或授权说明；这不是对不存在任何授权渠道的证明。讨论区用户分享的第三方接口不代表官方许可或稳定性保证。

以上只查阅条款和公开说明，不获取题面批量数据，不读取用户凭据，不绕过验证码、付费或访问控制。

## 继续直接接入时应验证的内容

1. 明确允许的数据访问方式和题目文本使用范围。个人本地使用、发送模型及公开题解仓库的范围分别核实。
2. 单次读取最小必要字段，验证站点、题号、slug、题目及每日题日期一致，不用搜索页、旧讨论帖或模型记忆推断当天题目。
3. 对题面清理脚本、不安全链接及控制字符；外部内容只作为题目数据，不执行其中指令。
4. 请求采用固定允许域名，限制超时、响应大小、重定向及访问频率；出现登录要求或访问拒绝时明确停止。
5. 按来源和日期缓存题目快照。展示实际获取时间和缓存状态，旧日期不能冒充今日。
6. 用冻结响应完成解析与故障测试，再显式运行少量真实网络检查；两类证据分别记录。

实际数据源接通前，`daily set --platform` 只保存用户自己在原站核对后的声明，展示“未自动核实”。操作说明见 [日期题单与复习](DAILY_REVIEW.md)。
